- The FFmpeg component archive `components/ffmpeg-1041abdc962f.zip` is the immutable commit archive for the `n8.1.3` security release. The previous release pinned `n8.1.2` (commit `1c2c67c0b9f7f66ab32c19dcf7f227bcd290aa4c`).

## Security fixes included in this upgrade

FFmpegKit 8.1.9 updates the bundled FFmpeg from `n8.1.2` to `n8.1.3`. The upstream source pin file documents four CVEs fixed in `n8.1.3` and states which of them apply to this audio build:

- `CVE-2026-64830` (VobSub demuxer, `avformat/vobsub`) — upstream records this as reachable in this build.
- `CVE-2026-64835` (ADX decoder, `avcodec/adx`) — upstream records this as reachable in this build.
- `CVE-2026-64831` (Vulkan HEVC) and `CVE-2026-64832` (NVDEC) — upstream records these as not applicable here because the build enables no Vulkan path and Android has no NVIDIA decode path.

Bundle verification confirmed that the VobSub demuxer and ADX decoder identifiers are present in `libavformat.so` and `libavcodec.so` for both shipped ABIs. This establishes that the fixed components are included in the distributed binary. It does not by itself establish that ordinary app input reaches them, because which demuxer or decoder handles a given file depends on that file's format. Do not describe these CVEs as proven exploited or proven unreachable in the app without input-level testing.

## Replacement and remaining limits

The Gradle project links the native shared libraries supplied by the AAR. A replacement workflow is to build a compatible LGPL audio AAR from the pinned recipe, place it at `app/libs/ffmpeg-kit-audio-replacement.aar`, and replace the `implementation("dev.ffmpegkit-maintained:ffmpeg-kit-audio:8.1.9")` dependency in `app/build.gradle.kts` with `implementation(files("libs/ffmpeg-kit-audio-replacement.aar"))`. For an independently installable modified app, set `applicationIdSuffix = ".modified"` in the release build type, then rebuild and sign the APK with your own key. Android treats the suffixed application ID as a separate app, so it can be installed alongside the original without replacing or deleting the original app's private data. The modified app starts with its own app data; data is not automatically copied from the original installation. These build and install steps describe a practical relink route but have not been exercised or verified against the release APK.

The release asset hash comparison identifies the exact AAR Maven resolved and ties it to the upstream release binary. The accompanying corresponding-source archive includes all native source pins recorded for this audio variant, with integrity hashes and license-bearing upstream archives. This audit did not rebuild the AAR from the pinned source, compare object files, or test the modified-library relink/build/install path. Keep the matching corresponding-source materials clearly available for each APK release, and verify the replacement workflow before making claims about satisfaction of every applicable LGPL condition. This note and archive document corresponding source but are not a certification of every LGPL condition.
